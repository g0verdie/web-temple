Grounding Context

Codebase context. web-temple is an Express 4 + EJS server-rendered MPA (CommonJS, Postgres + Redis, Bull workers, no bundler/framework). It is on dev at HEAD 47cb66f. Hard constraints stay in force (no TS/bundler/framework; strict CSP, no inline script/style; services own SQL; NODE_ENV==='test' branches are load-bearing).

The wall behind us. Five reconciliation scouts read the planning corpus and then verified each item against current code/git. Everything below already shipped and was cut from "remaining": the entire U1–U14 hardening suite (SIGTERM graceful-drain, pg-pool error + crash handlers, Sentry PII scrub, /health + /ready, SEO OG/JSON-LD/sitemap/noindex, donation form + metrics cache, reserved-name guard, branded 500, completed .env.example, console.*→winston), the 11 UX items, the CSP fixes (password reset, Rabbi tour, CMS editor — JS externalized, driver.js/Quill vendored), trust proxy, the HMAC-signed one-click /unsubscribe, seed content that meets the PRD Board-demo minimums, and the donation 3-strike alert / CSV export / receipt-PDF / pluggable provider seam. So the surface below is small and almost entirely non-feature-code.

What that leaves falls into four tiers: (1) launch blockers — stand up and cut over a server, set real secrets, make email deliverable, fix the broken real-account script, get legal pages reviewed, wire monitoring; (2) pre-real-money — productionize PayPal (Board-gated, mock by design); (3) launch QA gates — five human verification passes that need a real environment; (4) polish — small reliability/hygiene items, none blocking.

External grounding (production-readiness research) cross-checks the internal plan and adds a few commonly-missed items: PM2 kill_timeout must exceed worst-case drain; an external uptime probe + dead-man's-switch + disk-full + cert-expiry alerts (a single box can't self-alert); SPF/DKIM/DMARC plus a PTR/rDNS record and the RFC 8058 one-click List-Unsubscribe header for the 2024+ Gmail/Yahoo bulk rules; and for PayPal: verify the webhook over the raw request body, store an idempotency key per transmission-id, and use Subscriptions API v2 (Billing Agreements is deprecated). Institutional learnings add two: "ops code is production code" (the backup scripts were historically buggy — run the restore drill), and adversarially review admin/Rabbi route gating when you create real staff accounts.

Set the real production secrets

Launch blockerDeploy & opsOperator
What The ~14 documented vars need real values on the box. The load-bearing ones: ENCRYPTION_KEY (PII reads/writes throw without it), JWT_SECRET (auth forgery if weak/shared), APP_URL/APP_BASE_URL (or every email link is http://localhost:3000), and TEMPLE_LEGAL_NAME/TEMPLE_EIN/TEMPLE_ADDRESS (or tax receipts are legally invalid). Store them in a chmod 600 file outside the repo (systemd EnvironmentFile= or PM2 env_file); validate-on-boot so a missing var fails fast. Do not set ADMIN_TOKEN (that middleware was deliberately removed in U10).
Basis direct .env.example is fully expanded and documented (U13), but the committed .env has no SMTP/APP_URL/CAPTCHA/TEMPLE values; receiptPdfService.js:9-11 falls back to placeholders.
Rationale Cheap but unskippable, and the receipt-identity values have a legal dimension (a 501(c)(3) receipt without a real EIN/legal name isn't valid).
Downsides None technical — but rotate any secret already committed in .env history before go-live.

Make email actually deliver (SMTP + DNS auth + captcha)

Launch blockerEmail & DNSOperator · DNS
What Four coupled pieces: (a) pick an SMTP provider/ESP and set SMTP_* — without it every send is silently mocked (logged, never sent); (b) publish SPF + DKIM + DMARC records and a PTR/rDNS on the sending IP (the 2024+ Gmail/Yahoo bulk-sender rules); (c) set both CAPTCHA_SITE_KEY and CAPTCHA_SECRET together — set only one and the contact form's widget passes but the server rejects every submission; (d) add the RFC 8058 one-click List-Unsubscribe/List-Unsubscribe-Post header (the body already has an unsubscribe link, but the header isn't set).
Basis direct emailService.js:6-13 returns early with a winston log when SMTP_HOST is absent; no SPF/DKIM/DMARC anywhere in repo (deferred as an operator DNS task); contact.js:27 falls back to hCaptcha's test sitekey; no List-Unsubscribe header in src/. external Gmail/Yahoo/Microsoft bulk-sender authentication + alignment requirements.
Rationale Password reset, donation receipts, reminders, and announcements all ride on email. Unauthenticated mail in 2026 lands in spam or is rejected outright — silent failure that looks like the feature is broken.
Downsides DNS propagation + a warm-up period; verify with mail-tester before relying on it. Mostly DNS/console work, no code (except the small header addition).
