Making the web-temple UI Prettier

Seven ranked, evidence-grounded directions for lifting the public site from "functional and flat" to warm, reverent, and polished — all buildable in vanilla CSS / EJS within the strict CSP and the verified accessibility budget. florencetemple.org was used as an inspiration reference (a floor to clear, not a ceiling).

Codebase Context

Stack & delivery. Express 4 + EJS server-rendered MPA — no bundler, no framework, no TypeScript (intentional). Styling is plain CSS: public/css/main.css (global, ~630 lines, holds the :root token block) plus ~13 per-page stylesheets injected via a stylesheets[] array in src/views/layout.ejs.

Hard constraints any idea must respect.

  • Strict CSP — styleSrc/scriptSrc/fontSrc are 'self' (+ hCaptcha). No inline <style>, no style=, no third-party CSS/font CDNs. A Jest guard (__tests__/security/cspViewCompliance.test.js) fails the build on any inline style/script. ⇒ web fonts must be self-hosted in public/fonts/; all styling ships as external CSS from 'self'.
  • Accessibility budget (jest-axe in CI) — keep WCAG AA (text ≥4.5:1, non-text ≥3:1), the 3px gold focus ring + 2px offset, 44px touch targets, and color+non-color error cues. Any new palette must re-clear these.
  • Ratified direction — "Modern Reverence" (deep navy + warm gold + soft neutrals; serif headings, sans body; airy 8px spacing; calm motion). Documented in ux-design-specification.md but largely unbuilt. Tailwind / Bootstrap / MUI were explicitly rejected.

Current state (the floor we're lifting).

  • Color drift. main.css ships --color-accent: #d69e2e, but --color-gold is referenced in contact.css (and others) and never defined in :root — so those references silently fall back to a hardcoded #c9a961. At least three different golds ship in CSS (#d69e2e, #c9a961, #b8860b), and the docs name still others (#daa520, #d4a574). The high-contrast block darkens primaries but not the accent. No dark mode.
  • Typography. System sans stack everywhere; no web fonts and public/fonts/ doesn't exist; heading sizes are stepped across three breakpoints (no clamp()); text is measured by pixel boxes, not ch. The documented serif-heading direction was never built.
  • Imagery & identity. The homepage hero is text only over a flat blue gradient. The only image asset in the repo is favicon.svg (a Star of David in brand colors). No community photos, no icon set, no header logo.
  • Components & motion. Flat cards (mixed 6/8px radii, light shadows); sections are mostly flat (one alt-band already exists on the countdown section). Several public interactive surfaces — donation amount buttons (.amount-level), .btn-link, public .event-card — have no hover/focus feedback. A global prefers-reduced-motion block already exists in main.css.

Reference (florencetemple.org). Functional but dated — an architectural hero (the building, not people), sans-serif with no type personality, a utilitarian photo-grid, a cool/institutional palette with gold not deployed, unstyled forms, no section rhythm. Worth keeping: generous whitespace and prominent service-times / donate / contact.

Topic Axes

  • A1 — Color system & design tokens. Palette, the gold-drift consolidation, warm base, contrast, dark mode.
  • A2 — Typography. Self-hosted web fonts, serif/sans pairing, fluid scale, hierarchy, measure.

  • A4 — Components & layout rhythm. Cards, buttons, nav, footer, section dividers/alternation.
  • A5 — Motion & micro-interactions. Hover/focus feedback, transitions, reduced-motion coverage.

Consolidate the gold accent into one defined token

Today: a different gold per file (and one referenced-but-undefined). After: a single --color-gold every page inherits.
Description
Define --color-gold (and a paired --color-gold-dark for AA text) once in the main.css :root, alias --color-accent to it, then mechanically replace the scattered hardcoded golds across the per-page stylesheets with var(--color-gold). Add the missing darkened-gold line to the prefers-contrast: high block so the accent is governed in high-contrast mode too. The canonical hex is a one-time design call (review on cream before committing).
Basis
direct: contact.css uses color: var(--color-gold, #c9a961) while main.css :root defines only --color-accent: #d69e2e — --color-gold is never defined, so every reference falls back to the orphan #c9a961. The prefers-contrast: high block overrides primary/secondary but not the accent. (Verified against the repo; ≥3 distinct golds ship in CSS — #d69e2e, #c9a961, #b8860b.)
Rationale
This is the cheapest move with the widest blast radius and it fixes a genuine latent bug, not just a style nit. Once the token resolves, every other idea here (warm base, card rule, focus ring) has one correct gold to reference instead of a guess.
Downsides
Touches ~5 CSS files; the substitution is mechanical but the canonical hex is a judgment call that benefits from a quick visual review (and a re-run of npm run test:a11y to confirm contrast).
2.

Self-host a serif/sans "Modern Reverence" type system

A2 · TypographyConfidence High (92%)Complexity Low–MedLoudest premium signal
Shabbat services & community
A warm humanist sans for body copy keeps long passages effortless to read, while a calligraphic serif gives every heading the gravitas of carved stone. (This document is set in that pairing.)
A serif heading + sans body pairing — the single change that most shifts perceived quality.
Description
Self-host one display serif for headings (Cormorant Garamond, Marcellus, or Quattrocento) and a humanist sans for body into public/fonts/ via @font-face (WOFF2, Latin subset, fetched with google-webfonts-helper — no CDN). Define --font-serif / --font-sans and apply the serif to h1–h4 in main.css. No template edits — the cascade carries it to every page.
Basis
direct: ux-design-specification.md documents the serif-heading "Modern Reverence" direction and proposes --font-serif, but main.css ships a system sans stack only and public/fonts/ doesn't exist. direct: server.js CSP fontSrc: ['self'] permits self-hosted fonts. external: Cormorant Garamond/Lato, Marcellus/DM Sans, Quattrocento/Questrial are established "modern + traditional" pairings; google-webfonts-helper produces CSP-clean self-hosted WOFF2.
Rationale
Typeface is the loudest single signal of "a place of worship" vs "a generic Node app," and it's the one ratified-but-unbuilt brand decision. One @font-face block + one heading rule lifts every screen at once.
Downsides
Adds ~30–60 KB of self-hosted WOFF2 and a one-time setup step. Keep serif for headings and an accessible sans for body (some display serifs read thin at small sizes); re-clear AA + zoom on the chosen faces.

Description

Engineer the slot now (a background-image on a hero class) so a photo drops in without a redesign; ship a CSS-only fallback (see also the deferred Star-of-David texture) until a photo exists.
Basis
direct: the hero is background: linear-gradient(135deg, var(--color-primary), var(--color-secondary)) with no image (main.css / home.ejs); the spec explicitly calls for a real sanctuary photo, unimplemented. direct: CSP imgSrc allows 'self' + https:. external: a dark-scrim gradient over hero photography is the standard accessible-text-over-image pattern; exemplars emanuelnyc.org, bj.org lead with real community imagery.
Rationale
The hero is the first thing every visitor sees and currently the least "temple" surface on the site — an abstract blue rectangle. One real photo does more for "warm and inviting" than any amount of CSS, and the scrim keeps it CSP- and AA-safe. It's also where florencetemple.org's one strength (showing the actual place) beats us today.
Downsides
Needs a good photograph (the real dependency) and per-image scrim tuning to hold contrast. Ship the CSS/SVG fallback first so the hero improves even before a photo is sourced.

A warm cream canvas with deliberate section rhythm

A1 / A4 · Color & rhythmConfidence Med–HighComplexity Low–Med
Cream — primary sections (#faf7f0)
Warm sand — alternating band (#f0ebe0)
Navy — anchor band / header / footer
Cream — primary sections
Swap clinical white for a warm cream base, then alternate cream / sand / navy for breathing rhythm — no markup changes.
Description
Replace the cool #ffffff / #f7fafc backgrounds with a warm cream --color-bg (~#faf7f0) via the token, and turn the single existing alt-band into a deliberate site-wide rhythm: cream primary sections, a warm-sand alternating band, and the navy as a high-contrast anchor. The gold accent reads richer on cream than on stark white.
Basis
direct: main.css :root sets --color-bg: #ffffff / --color-bg-alt: #f7fafc; the countdown section is the one section that already uses an alt background, so the pattern exists but isn't applied as rhythm. reasoned: #faf7f0 against --color-text: #2d3748 is ~10:1 — comfortably AA. external: a warm-cream base is the canonical warm register on Jewish-community exemplars (emanuelnyc.org, bj.org) — verify the specific pairing visually before committing.
Rationale
This is the change that most shifts the site's felt temperature from "institutional portal" to "community home," and because it's a token swap, all 13 stylesheets inherit it for free.
Downsides
The ripple surface is large (the bg token is used widely) so it needs a full visual pass + a11y re-run; the alternation pattern wants a quick design review per page rather than a blind global toggle.

Generalize the featured-announcement gold accent into one card signature used by events, streams, and announcements.
Description
Define --radius and a single shadow recipe as tokens, then give the card family one signature: a 3px gold top-rule (base transparent → gold on hover, to avoid layout shift) plus a calm layered shadow. Apply across .event-card, .stream-card, .announcement-card, calendar .card.
Basis
direct: announcements.css already uses a gold left-border on .announcement-card--featured (#b8860b) — proof the accent already reads as "important" here; cards currently use mixed radii (6px/8px) and several shadow recipes. external: a gold top-border card with a soft shadow is a standard warm-institutional card pattern.
Rationale
Cards are the most-repeated component on the site (events, streams, announcements, calendar). One coherent treatment in main.css makes every list look designed by the same hand — and every future card inherits it.
Downsides
A solid top-border on hover can cause a 3px layout shift — mitigate with a transparent→gold transition. Target named card classes (avoid wildcard selectors). Pairs best after idea 1 defines the gold.
6.

Fluid clamp() type scale + a 65ch reading measure

A2 · TypographyConfidence HighComplexity LowPure CSS
Description
Replace the three per-breakpoint font-size declarations for .hero-headline and .section-title with one clamp() each (e.g. clamp(1.5rem, 4vw + .5rem, 3rem)), and cap prose containers at max-width: 65ch. Headings then scale continuously instead of snapping at 768px / 1024px, and line length stays in the comfortable reading band.
Basis
direct: main.css declares .hero-headline and .section-title font-sizes at three discrete breakpoints; there is no clamp() or ch measure anywhere in public/css/. external: clamp() fluid type + ~65ch measure are well-established readability best practices (MDN, Every Layout).
Rationale
It removes the most visibly jarring transition on the site — the size jump at breakpoints — in two declarations, with no new assets and no a11y risk (relative units respect zoom). It also lets the new serif headings (idea 2) shine at every width, not just desktop.
Downsides
The clamp() parameters are starting points; verify the interpolated sizes at 375 / 600 / 768 / 1024 / 1440px so nothing reads too small or too large mid-range.
7.

Restore interactive feedback on the "dead" surfaces

A5 · MotionConfidence HighComplexity LowTrust surface
Description
Define a --transition-base timing token, then add calm hover/focus feedback (gold border + soft lift, and a clear selected-state for the donation amounts) to the interactive surfaces that currently have none: .amount-level donation buttons, .btn-link, and the public .event-card. The existing global prefers-reduced-motion block covers the new transitions automatically.
Basis
direct: the motion evidence shows .amount-level (donation radios), .btn-link, and the public .event-card have no hover/focus rules, while main.css already has a global prefers-reduced-motion block. (Correction from verification: .member-card's inner link does have hover — so the gap is narrower than first scoped.) external: a gold underline/lift on hover matches the existing nav/button vocabulary.
Rationale
An element with cursor: pointer and zero response reads as broken — and the worst offender is the donation amount button, the highest-stakes click on the site. Unifying the motion language is what makes "polished" legible; it's near-free given the existing timing and reduced-motion safety net.
Downsides
Per-file edits across donations.css / calendar.css; the hover/selected look is a small design decision (a gold border + light shadow is enough). Lower visual "wow" than ideas 1–3 but high trust value.
